# 使用与故障处理

## 正常启动

Codex 在第一次调用 `aialra-shopping-browser` 工具时启动 MCP

插件先检查独立 Chrome 是否已经运行

没有运行时启动一个独立 Chrome；已经运行时让当前 MCP 连接同一个 Chrome

不需要手工运行常驻服务

Chrome 使用随机 CDP 端口，并且只绑定 `127.0.0.1`

这个端口不会暴露到局域网或公网

## 第一次登录

1. Agent 打开目标网站
2. 页面要求登录时，Agent 停止
3. 用户直接在独立 Chrome 中登录
4. 用户完成后通知 Agent
5. Agent 从当前页面继续

账号、密码和验证码始终由用户输入

## Chrome 没有出现

先确认系统安装了 Google Chrome

再运行

```bash
npm run test:mcp
```

测试通过表示插件、Node、MCP 和 Chrome 可以正常配合

测试失败时查看脱敏后的错误类型，不要上传浏览器资料或完整日志

## 多个任务同时使用

多个任务会连接同一个独立 Chrome，不再分别启动使用同一资料的浏览器进程

每个任务在第一次访问时创建自己的标签页，并只操作自己的标签页序列

任务结束时只能关闭自己的页面，不能关闭其他任务的标签页

如果仍出现“资料正在使用”，说明旧版插件进程或人工启动的 Chrome 正在占用资料

关闭使用 AIALRA 独立资料的旧窗口后重新调用工具；不要删除日常 Chrome 资料

## 清除登录状态

关闭独立 Chrome

把以下目录移动到废纸篓

```text
~/Library/Application Support/AIALRA Shopping Browser/Profile
```

下次启动会创建全新的空白资料

这个操作只能清除独立购物浏览器，不影响日常 Chrome

## 修改资料位置

设置

```bash
export AIALRA_SHOPPING_BROWSER_PROFILE_DIR="/你选择的本地目录"
```

目录必须位于插件仓库外

不要把整个主目录、磁盘根目录或共享同步目录设为资料目录

需要指定浏览器程序时设置

```bash
export AIALRA_SHOPPING_BROWSER_EXECUTABLE="/浏览器程序的完整路径"
```

## 页面要求验证码

Agent 停止自动操作

用户亲自完成验证码

失败后不自动重复尝试

验证码持续出现时结束本次运行并报告覆盖缺口

## 页面显示限流

Agent 返回 `rate-limited`

本次运行不自动重试，不切换代理或浏览器

稍后开始新的用户任务可以重新预检

## 页面结构改变

Agent 返回 `layout-changed`

平台 Skill 维护者根据新的可见结构更新字段映射和测试

不要为了交付结果而猜测字段

## 页面突然变成空白页

`about:blank` 只表示当前标签页面丢失，不能直接判断用户退出登录

浏览器进程仍然可以响应时，Agent 在同一标签重新打开当前节点的官方入口一次

重新打开后根据登录弹窗、用户入口、结果区域和工具错误等多个信号判断

页面再次变成空白时返回 `layout-changed`，并记录发生空白页之前的具体工具动作

## 页面快照保存位置

页面快照默认只通过 MCP 标准输出返回，不生成原始文本文件

Agent 即使提供 `browser_snapshot filename`，启动器也会移除该参数

截图和下载仍进入仓库外的 MCP 输出目录

结构化证据必须先移除临时令牌和跟踪参数，再由平台 Skill 保存

## 宿主策略阻止

Agent 返回 `policy-blocked`

这个状态表示当前任务的工具执行层明确拒绝访问

本插件不能在同一受阻任务中作为绕过路径

安装新插件后需要新建任务，新任务会根据实际加载的工具重新判断
